# 第四轮报告：肤色精准选区 / 均匀度 / 整图色彩 / 仿色 / AI 接入

日期：2026-10-13

## 本轮按你的要求新增的功能

| 你的要求 | 实现 |
|---|---|
| Lab 第一个值是明度吗；a、b 在 10–20、差值不超过 5 即正常 | 是。这条规则已做成“经验快速判定”，每次肤色分析都会显示；可在 `skin_presets.json` 中修改，各风格也有自己的区间 |
| 精准选中皮肤（脸部、身体分别分析） | 自动抠皮肤（`core/skin_mask.py`），可选套索；“部位”选择；脸部和身体都分析过后自动比较两者差异 |
| 自动抠的皮肤多了或少了，可以手动添加删除 | 皮肤蒙版编辑：画笔添加/擦除、魔棒添加/删除、撤销、恢复自动（`core/mask_edit.py`、`ui/mask_editor.py`） |
| 整块皮肤色相是否均匀（一块橙一块黄要标出来） | `core/skin_uniformity.py`：按小块比较色相和饱和度，标出偏黄、偏红橙、偏青绿、偏洋红、缺色发灰、饱和度偏高的位置，并给出均匀度评分 |
| 发灰（缺色、缺饱和度）要体现 | 三个层面：皮肤饱和度 C\*/L\* 与目标范围比较、局部发灰块、整图色彩丰富度（Hasler-Süsstrunk 指标） |
| 更多肤色风格（黑皮、小麦等） | 新增韩系、欧美、港风、新中式、小麦、古铜、深肤色，共 12 种 |
| 6:3:1、整体颜色统一（例如所有绿色统一成一种） | `core/palette.py`：6:3:1 比例与改进建议；某种颜色的统一度，标出不统一的位置，并给出混色器各通道的色相/饱和度收拢建议 |
| 黑金、青橙、粉蓝等怎么调（校准、HSL、曲线） | 7 种风格模板（`data/grading_styles.json`）：计算差距，给出混色器、颜色分级、曲线的具体建议和常用做法 |
| 仿色分析：对方是什么色彩、差多少、合不合适 | `core/reference_match.py`：相似度、影调曲线点、偏色、阴影/高光色调、通道、主色对应、适合度 |
| 选点支持多种大小 | 1×1、3×3、5×5、11×11、31×31、51×51、101×101（与 PS 吸管一致），框选层中可用 `[` `]` 切换 |
| AI：可以调用 Codex 会话、Claude 会话或 DeepSeek API | 本机 Claude Code（`claude -p`）、本机 Codex（`codex exec`）、DeepSeek API、Claude API（官方 SDK），以及“复制给 Agent”和命令行 `colordoctor analyze ... --json` |

## 隐私与离线

- **默认完全离线**：联网代码只存在于可选的 `colordoctor/ai` 包中，界面启动时不会导入它（有测试检查）。
- **何时会发送内容**：只有在设置中开启 AI 点评（会弹出确认）并点击“AI 点评”时才会发送。默认只发数值，勾选后才会附带 768 像素的缩略图（写入系统临时目录）。

开发中发现并修复的问题：

- 魔棒在边界取 3×3 平均色导致种子点落空；
- 偏黄时 a\* 自然下降，被误判成“偏青绿”；
- 均匀度评分过于宽松；
- 风格的阴影/高光色调被鲜艳物体干扰（改为只看接近中性的像素）；
- 窗口关闭后后台线程仍向已销毁的对象发信号；
- 色轮的散点包含了非皮肤像素。

另外发现一个现象：JPG 的色度二次采样会把**单像素**的杂色抹掉，所以真实照片里能被检测到的是至少几个像素大小的杂色块。这符合实际情况，已经写进测试说明。

## 仍未验证 / 风险

1. **Windows 专属部分未在 Windows 上运行过**：`claude -p` / `codex exec` 的实际参数（尤其是读取 stdin 和附带图片的方式）、显示器 ICC、全局快捷键、多显示器、套索和蒙版编辑在真实屏幕上的手感。见 `docs/WINDOWS_HANDOFF.md`，共 14 项。
2. **经验值未经真实样片校准**：肤色风格、风格模板的色区，以及滑块换算常数（色相 ±100 ≈ ±30° 等）都是经验值。
3. **自动抠皮肤基于颜色规则**：与皮肤颜色相近的物体可能被误选，需要用蒙版编辑修正。
4. **整图风格判断是数值层面的**：审美层面的判断（例如“合不合适”）可以交给 AI 点评，但 AI 的结论仅供参考。
