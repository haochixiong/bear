## 1. 根据你的反馈确定的设计（第三版）

| 你的要求 / 问题 | 决定 |
|---|---|
| 方案 C：全新的精简应用 | 不导入上游代码。只参考上游的屏幕取色交互思路，并修正了它在多显示器和高 DPI 下的缺陷 |
| 判断照片是否“脏、发灰”，并且**指出位置** | `core/contamination.py`：检测“对立色混入”和“局部发灰”，输出像素级标记图和编号位置框；界面中的“问题位置”页负责高亮显示 |
| 打点取色，显示 Lab 等数值 | 采样大小 1×1、3×3、5×5（默认）及更大；显示 HEX、RGB、HSB、HSL、Lab（D50/D65）、LCh、OKLab、OKLCH、相对亮度 |
| 日系、法式、暗调、Cos 的肤色范围 | `data/skin_presets.json`：5 种风格的 Lab 区间，可由用户覆盖，也可以从参考作品取样生成目标 |
| 给出 PS 色相/饱和度、色彩平衡等参数 | `core/ps_models.py` 和 `core/recommendations.py`：曲线（对平均色精确）、色彩平衡、色相/饱和度（估算）、可选颜色（方向和起步值）、Camera Raw（方向） |
| 能否直接按标准 sRGB 计算？用 ICC 会不会导致不同设备结果不同？ | 输出统一为标准 sRGB 数值和 Lab D50（与 Photoshop 一致）。读取显示器 ICC，是为了把 Photoshop 的显示转换反推回去，从而**消除**设备差异。不做色彩管理的软件可以切换为原样读取。详见 README 的“色彩管理”一节 |
| 1. 全部做完 | 屏幕取样（实时取色和冻结框选）和 JPG 文件**都**已实现 |
| 2. 快捷键 | Ctrl+Alt+Shift+Z（锁定读数）和 Ctrl+Alt+Shift+X（框选）。避开了 Photoshop 已占用的 C、E、N、S、W、K、M、B、L、T、O、P 等键，并且可以修改 |
| 3. scikit-learn 是什么 | 一个机器学习库，上游用它来“提取主色”（把颜色自动分组）。我们改为自己实现，打包体积更小，结果也可以复现 |
| 4. 删除 bearlab.py | 已删除 |
| 5. 自己查找肤色资料 | 已查找并整理，来源和推导过程见 README |
| 6. 写完代码以及 Linux 上能测的部分 | 已完成；Windows 上需要做的事见 `docs/WINDOWS_HANDOFF.md` |

另一个技术决定：Lab 默认使用 **D50 白点 + Bradford 色适应**，与 Photoshop 信息面板一致。sRGB 红色为 (54.3, 80.8, 69.9)；CIE D65 的数值另外显示。

开发过程中发现并修复的问题：

- 两步对比时，问题区会被误当成第二个参考区；
- 降采样后，标记图与原图的对齐需要确认；
- 总分公式会把“明显”稀释成“轻微”；
- 选区不完整时，Hue/Sat 的明度参数过大；
- 自检时调用 `app.exec()` 会干扰后续测试。

**另外做的打包验证**：在 Linux 上用 PyInstaller 按同一份 spec 打包，`--selftest` 输出 `SELFTEST OK`。

**性能**（2400 万像素选区）：区域分析 0.4 秒，肤色分析 0.6 秒，整图扫描 0.5 秒，均在后台线程中运行。

## 5. 尚未验证 / 风险（如实说明）

1. **Windows 专属代码没有在 Windows 上运行过**：读取显示器 ICC（`GetICMProfileW`）、全局快捷键（`RegisterHotKey` 和 PyQt6 `nativeEventFilter` 的返回值类型）、多显示器混合缩放下的对齐、exe 打包。请按 `docs/WINDOWS_HANDOFF.md` 第 1 节逐项验证。
2. **肤色风格区间**是根据资料和经验推导的，没有用真实样片校准。我没有找到“日系、法式”这类风格的权威量化标准，行业里只有经验做法。
3. **色彩平衡、色相/饱和度、可选颜色的数值**是模型估算，没有和 Photoshop 的实际输出对比过。校准方法见交接文档第 2 节。
4. **整图扫描**没有语义信息，可能把画面中真实存在的小物件（例如蓝衣服上的黄色纽扣）当作可疑位置。界面已经说明“请逐处确认”。
5. **PyQt6 是 GPL 许可**。如果要闭源发布，需要购买商业许可或改用 PySide6。
6. 项目本身**还没有选择许可证**（仓库中没有 LICENSE 文件），需要你决定。
