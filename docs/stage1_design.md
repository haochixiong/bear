## 0. 方向调整

根据反馈：

1. 采用**方案C：全新的精简应用**。不导入上游代码，只参考其中有价值的实现。
2. 产品**不是图片浏览器**，而是一个**辅助取色器和色轮**。它悬浮在 Photoshop、ACR 或任意看图软件旁边，直接从**屏幕**上取样，然后给出颜色数据、诊断和调整建议。

这会改掉原需求中的几条。请确认以下替换：

| 原需求 | 新方案 |
|---|---|
| 打开 JPG，读取原始像素；不把屏幕取色作为主要数据来源 | **屏幕取样是主要数据来源**。第一版不再打开图片文件 |

其余要求都保持不变：四种模式、区域统计、可解释的脏色风险、参考对比、ACR/PS 调整方向、中文界面、离线运行、不修改图片、测试驱动开发、误报专项测试。

## 1. 产品形态

一个**小尺寸、可以置顶的工具窗口**（约 420×860），放在 Photoshop 旁边使用：

```
┌──────────────────────────────┐
│ [单点] [通用区域] [人像肤色] [参考对比] │  ← 模式
│ [◎ 实时取色] [▭ 框选屏幕] 半径:5×5 ▾ 📌置顶 │  ← 取样方式
├──────────────────────────────┤
│        色轮 / 色相-色度平面          │  ← 核心可视化
│   · 当前点或区域像素散点、密度        │
│   · 肤色参考扇区                      │
│   · 参考区 ○ / 问题区 △ 的中心和箭头  │
│   · 对立色扇区高亮                    │
├──────────────────────────────┤
│ 明度 L* 分布条（P10 / P50 / P90）    │
├──────────────────────────────┤
│ 结论卡片：问题 / 证据 / 置信度        │
│ ▸ 调整方向（ACR / PS）                │
│ ▸ 详细数据（可展开）                  │
├──────────────────────────────┤
│ 本次取样历史（缩略色块，可回看、可设为参考）│
└──────────────────────────────┘
```

### 取样方式

1. **实时取色**：
   - 打开后，鼠标在任意窗口上移动时，工具会持续显示光标处的颜色。
   - 显示的是 1×1、3×3、**5×5（默认）**或自定义半径的平均值，刷新率约 15 fps。
   - 按**全局快捷键**锁定当前读数。锁定时不需要切换窗口，Photoshop 保持焦点。
2. **框选屏幕**：
   - 按钮或全局快捷键触发后，先隐藏本工具窗口，再**冻结所有显示器的截图**，然后显示全屏覆盖层，带放大镜。
   - 在覆盖层上可以单击取点，也可以拖动框选区域。在参考对比模式下，依次框出“参考区”和“问题区”。按 Esc 取消。
   - 冻结截图的作用是：框选过程中 Photoshop 的画面不会变化，本工具窗口也不会混进取样。
3. **历史记录**：本次会话中的每次取样都保存为“像素块和元数据”，只存在内存里。可以回看，可以设为参考区，也可以清除。

## 2. 参考上游代码的地方

上游的 `core/screen_color_picker.py` 采用“全屏覆盖层 + 放大镜 + 十字准星”，思路可以借鉴，但有以下缺陷，我们重新实现时会修正：

| 上游实现 | 问题 | 我们的做法 |
|---|---|---|
| 只截取窗口所在的那一块屏幕，覆盖层却用 `availableGeometry`（不含任务栏） | 截图和覆盖层坐标错位；**多显示器**时只能取一块屏幕 | 逐块屏幕截图，按每块屏幕的几何位置拼接，覆盖层按每块屏幕各建一个 |
| 直接把 `QCursor.pos()`（逻辑坐标）当作截图像素坐标 | Windows 缩放比例不是 100%（例如 125%、150%）时**取错像素** | 按每块屏幕的 `devicePixelRatio` 换算到物理像素 |
| 每 16 ms 对整张截图调用一次 `toImage()` | CPU 占用很高 | 截图只转换一次，转成 NumPy 数组，之后只切片读取 |
| 只能取 1×1 像素 | 不符合需求 | 支持 1×1、3×3、5×5 和自定义半径，并能框选区域 |

其他参考：上游 `rgb_to_lab` 的结果是正确的，作为交叉校验的基准；PyInstaller 的 `.spec` 和 `build_windows.bat` 作为打包模板。

如果某段代码是改编自上游（例如放大镜的绘制），会在 `THIRD_PARTY_NOTICES.md` 中保留 RNV 的 MIT 版权声明。

## 3. 屏幕取样的色彩管理（关键）

屏幕上的像素值是 Photoshop **按显示器配置文件转换之后**的“显示器 RGB”，不等于文档里的 RGB。

处理方式：

1. 通过 Windows 的 `GetICMProfileW`（用 ctypes 调用，不需要额外依赖）获取每块显示器当前的 ICC 配置文件。
2. 用 Pillow 的 `ImageCms`，以浮点精度把“显示器 RGB”转换为 XYZ 和 Lab，再计算 OKLab 等。显示用的 sRGB 数值也由此推算。
3. 读不到配置文件时，**假定显示器是 sRGB**，并在界面上提示“未找到显示器ICC，已假定为sRGB”。
4. 每次取样都在结果中显示：显示器名称、配置文件描述、是否发生了转换、缩放比例。

**原理**：Photoshop 做了色彩管理时，屏幕上显示的颜色在色度上近似等于文档的颜色。再用显示器配置文件反推，得到的 Lab 值近似等于文档的 Lab 值。对肤色这类在 sRGB 色域内的颜色，这个近似是可靠的。

**已知误差来源**（界面的“注意事项”中会提示）：

- 超出显示器色域的颜色在屏幕上已经被裁切。
- Photoshop 缩放**低于 100%** 时，单个屏幕像素是多个文档像素混合的结果。区域平均不受影响，单点读数会受影响。
- 屏幕上叠加的内容会混进取样：选区蚂蚁线、参考线、网格、校样颜色预览。
- Windows 的 HDR、自动颜色管理、夜间模式或 f.lux 等调色软件会改变像素值。
- 屏幕像素只有 8 位，存在量化误差。

## 4. 色轮（核心可视化）

坐标平面是 CIELab 的 a*b* 平面（或者 OKLab 的 a、b 平面，可以切换）。角度表示色相 h°，到中心的距离表示色度 C*。

- **单点**：显示一个点，并标出到中心的连线。
- **区域**：显示采样像素的散点和密度。从中能直接看出颜色是否集中、是否拖尾、是否有远处的离散点（对立色混入）。
- **肤色参考扇区**：一个淡色楔形，用来对照肤色。它是根据经验设定的，界面上标为“参考，非标准”。
- **参考对比**：参考区用 ○ 表示，问题区用 △ 表示，中间画一个箭头，表示从参考区到问题区的色相和色度变化。
- **对立色扇区**：诊断发现对立色混入时，高亮主色调对面的扇区和落在里面的像素。

色轮下方有一条明度 L* 分布条，标出 P10、P50、P90，以及高光和阴影的比例。

## 5. 分析核心（与界面完全解耦）

**输入**：

- `Sample`：一个 HxWx3 的 uint8 像素数组；
- `ColorContext`：来源（屏幕或测试）、配置文件、是否假定为 sRGB、显示器、缩放比例、取样时间。

**输出**：frozen dataclass。

核心模块**不 import PyQt**，测试时可以直接传入合成的 NumPy 数组。

| 模块 | 职责 |
|---|---|
| `core/color_spaces.py` | NumPy 向量化实现：sRGB、线性 RGB、XYZ、Lab(D65)、LCh、OKLab、OKLCH、HSV、HSL、相对亮度、ΔE00。用 Sharma 2005 的数据集校验 ΔE00 |
| `core/color_management.py` | 显示器配置文件 → XYZ 和 Lab（基于 ImageCms，跨平台，可以测试）。处理“假定为 sRGB”的回退 |
| `core/region_statistics.py` | 点采样和区域采样；越界裁剪；确定性的分层采样（上限 262,144 像素）；均值和中位数；标准差；P10、P50、P90；**按色度加权的色相圆形平均和离散度**；高光和阴影比例；裁切比例；主色聚类；异常色比例及其空间聚集度 |
| `core/portrait_analysis.py` | 肤色总体倾向；高光发黄、阴影发青或发绿；色度是否低于“随 L* 变化的期望区间”；判断选区是否混入了非皮肤区域 |
| `core/diagnosis_rules.py` | 7 个风险分项和总分（总分带上限）、置信度、严重程度（正常、轻微、明显、较强）、按“问题、证据、可能原因、调整方向、置信度、注意事项”结构输出 |
| `core/recommendations.py` | 映射为 ACR/PS 的调整方向；强度分为轻微、小幅、中等，标注为估计值 |
| `core/color_models.py` | 全部数据类 |

防误报规则沿用上一版设计（详见 `docs/stage0_audit.md` 第 6.4 节）：

- 低饱和、暗调、整体暖色调、青橙配色、少量零散噪点，都不会被判为“脏”。
- 两种对立色占比都很大时，判为“可能是有意配色”，不判为污染。
- 色度太低时，色相不计分，同时降低置信度。

**主色聚类**：建议**不依赖 scikit-learn**，自己用 NumPy 实现一个确定性的 k-means（固定初始化，约 60 行）。这样打包体积可以减少约 100MB，结果也完全可以复现。
