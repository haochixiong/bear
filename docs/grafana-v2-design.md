# SGE 监控看板重设计方案（v2）

> 状态：设计稿，未实施。不改采集器、告警规则、网络、TLS、业务服务；不覆盖已验收的 `sge-systems` / `sge-containers`。
> 依据：2026-10-04 技术验收快照（数量为快照值，不是实时采样）。
> 说明：设计方未能读取 `prometheus_onboarding_platform.py` 和验收报告原文。文中凡写成 `‹占位›` 的指标名、job 名，实施方须按现有看板 PromQL 替换并核实；凡标「待核实」的面板，核实前不得上线。

## 0. 一句话结论

**按「对象层级」拆页，用「清单表格 + 单对象详情」代替「多选全部主机 + 叠加曲线」。**

- 顶层 4 个入口：**总览 / PVE 集群 / 虚拟机 / 容器**。
- 另有 2 个详情页：**虚拟机详情 / 容器详情**，只通过点击钻取进入，单选、一次只看一个对象。
- 清单页只用表格、状态块、排行条，不画几十条曲线；曲线只出现在详情页。
- 状态统一编码：「未接入、无数据、陈旧、采集失败、已停止、不支持、未配置」各有不同文案和颜色，正常状态保持低调，只有需要处理的状态才用醒目底色。

## 1. 设计原则

| # | 原则 | 针对的现有问题 |
|---|---|---|
| P1 | 一页只回答一个问题：总览 = 哪里有问题；清单页 = 这一层谁有问题；详情页 = 这个对象怎么了 | 两个看板什么都放 |
| P2 | PVE 宿主机、虚拟机、容器分开展示，用链接表达从属关系（节点 → VM → 容器） | PVE 与 VM 混在一起，Docker 不分机器 |
| P3 | 清单页默认看到全部对象，但形式是**每个对象一行**，不是每个对象一条曲线 | 默认全选导致曲线爆炸 |
| P4 | 详情页**单选**，不提供 All | 同上 |
| P5 | 对象名称统一为 `VMID + 用途`，不显示 `ip:9100` | 图例拼接混乱 |
| P6 | 不确定的状态绝不显示绿色；没有数据绝不填 0 | 未支持网络被显示成 0、health=none 易被当成健康 |
| P7 | 看板阈值与 Prometheus 告警规则一致 | 避免「看板红了但没告警」或反之 |
| P8 | 新看板与旧看板并存，旧看板一字不改 | 验收对象不可覆盖 |

### 2.1 为什么是 4 + 2，而不是每台机器一页

- 21 台 VM、50 个容器，规模用**一张表**就能完整呈现，比任何大屏都直观。
- 「每台一页」会产生 17+ 份重复看板，改一个面板要改 17 次；详情页用变量参数化，一份即可。
- 详情页不放顶层导航，避免用户在没有选定对象时进入一个「空页」。

### 2.2 导航

- 每个 v2 看板顶部放 Grafana **Dashboard links**：
  - 链接 1：按 tag `sge-v2-nav` 列出 4 个顶层页（平铺，不用下拉），勾选 *Keep time range*。
  - 链接 2：按 tag `sge-v2-detail` 显示为下拉「详情」，勾选 *Keep time range* 和 *Include variables*。
  - 链接 3：「v1 已验收看板」下拉，指向 `sge-systems`、`sge-containers`（回退入口）。
- 所有钻取用 **data link**，URL 形如：
  `/d/sge-v2-vm?var-vmid=${__data.fields.vmid}&${__url_time_range}`
- 所有 v2 看板放到新文件夹 **「SGE 运维监控 v2」**；旧看板留在原文件夹原位。

## 3. 统一状态规范（所有页面共用）

### 3.1 状态码（按严重度排序，便于 `max()` 取最坏）

| 码 | 文案 | 含义 | 颜色（Grafana 命名色） | 呈现方式 |
|---|---|---|---|---|
| 空 | `—` | 查询无结果，原因未知 | `text` 灰 | 仅文字 |
| 10 | 正常 / 运行中 | 指标存在且在阈值内 | `green` | **仅文字或小圆点，不铺底色** |
| 11 | 未配置 | 容器 `health=none` | `text` 灰 | 仅文字 |
| 12 | 不支持 | 能力不存在，如老网管逐容器网络 | `text` 灰，斜体 | 仅文字，绝不显示 0 |
| 13 | 未接入 | 计划外、未部署采集（VM102/109/110/112 深度采集） | `text` 灰 | 仅文字，单元格虚线边框可选 |
| 20 | 已停止 | 对象本身停止（VM stopped、容器 exited） | `blue` | 浅色底 |
| 30 | 数据陈旧 | textfile 超过阈值未更新 | `purple` | 浅色底 |
| 40 | 警告 | 越过 warning 阈值 / warning 告警 | `orange` | 实色底 |
| 50 | 采集失败 | `up==0` 或 Docker 采集成功标志为 0 | `dark-purple` | 实色底 |
| 60 | 故障 / 严重 | 越过 critical 阈值 / critical 告警 | `red` | 实色底 |
| — | 曾 OOM | 历史标记 | `orange` | **仅橙色文字「曾OOM」，不铺底** |

规则：

1. **颜色只给需要动手的状态**：紫色 = 监控自己出了问题；橙/红 = 被监控对象有问题；蓝 = 停止（是否异常由人判断）；灰 = 信息性。
2. 11/12/13 只用于「覆盖/能力」类列，**不参与**对象综合状态的 `max()` 聚合。
3. 「采集在线」只能写成「采集在线」，不能写成「主机正常」「服务正常」。
4. 没有业务探测数据的地方不出现任何「服务健康」字样。
5. systemd 单元状态只代表该单元，面板标题注明「仅覆盖已配置单元」。
6. 已停止默认蓝色而非红色，因为当前没有「应运行清单」。若后续补充该清单（见 §9），可把「应运行却停止」升为 60。

### 3.2 数值阈值

不在看板里另立标准。实施时读取现有 Prometheus 告警规则，按规则中的 warning/critical 值设置看板阈值；规则未覆盖的指标采用下表缺省值，并在面板描述里写明「看板阈值，无对应告警」。

| 指标 | 警告 | 严重 |
|---|---|---|
| CPU 使用率（5m 平均） | 80% | 90% |
| 内存使用率（MemAvailable 口径） | 85% | 95% |
| 文件系统使用率 | 80% | 90% |
| inode 使用率 | 80% | 90% |
| Docker textfile 新鲜度 | > 3 × 采集周期 | — （直接判「陈旧」） |

### 3.3 名称与单位

| 对象 | 显示 | 说明 |
|---|---|---|
| VM | `114 监控平台` | VMID + 中文用途；hostname、IP 放独立列或 tooltip |
| PVE 节点 | `pve03` | |
| 容器（多主机上下文） | 表格中「主机」「容器」分两列；曲线图例 `{{container}} @ {{vmid}}` | 不再只写容器名 |
| 容器（单主机上下文） | `{{container}}` | |
| 文件系统 | `{{mountpoint}}` | device、fstype 放 tooltip |
| 网卡 | `{{device}}` | 默认排除 `lo|veth.*|docker.*|br-.*` |
| 百分比 | `percentunit`，0 位小数 | |
| 容量 | IEC（GiB） | |
| 网络速率 | bit/s（`bps`） | 运维习惯 |
| 磁盘速率 | B/s（`Bps`） | |

中文用途和 IP 不在指标里，由生成脚本里的**同一份清单字典**生成：表格 value mapping（vmid → 用途）和 VM 详情页头部文字。不新增采集。

## 4. 页面设计

网格单位：Grafana 24 列；高度单位为 grid row（约 30px）。尺寸写作 `w×h`，坐标写作 `(x,y)`。

### ① 总览 `sge-v2-home`

**回答：现在哪里有问题？** 默认时间 `now-6h`，刷新 1m，无变量。

| 网络入/出、磁盘写 | node_exporter rate，排除虚拟网卡 | 数值 | 「未接入」 |
| 容器 运行/总 | Docker 指标 | `22/22`；有非运行时蓝/橙 | 区分「未采集」（非 Docker 主机）与 `0/0`（VM119，采集正常无容器） |

D2 规则：

- **状态**：运行中（绿字）/ 已停止（蓝）/ 重启中（橙）/ 无数据。

- **新鲜度**：取该主机 textfile 年龄；超过阈值整行状态列覆盖为「数据陈旧」（紫），因为此时其他列都不可信。

## 5. 关键查询写法（原生 Grafana + PromQL）

> 占位约定：`‹node_job›` = node_exporter 的 job；`‹dk_up›` = 容器运行状态指标；`‹dk_ok›` = Docker 采集成功指标；`‹dk_net_cap›` = 网络采集能力指标；`‹dk_*›` = 其他容器指标。实施方以现有看板 PromQL 为准替换。

### 5.1 PVE 去重和 vmid 关联

```promql
# VM 身份（去重：6 个目标重复返回，按 id 合并）
max by (id, name, node) (pve_guest_info{id=~"qemu/.*"})

# 统一产生 vmid 标签，便于与 node_exporter 指标关联
label_replace(max by (id) (pve_cpu_usage_ratio{id=~"qemu/.*"}), "vmid", "$1", "id", "qemu/(\\d+)")
```

注意：迁移瞬间不同目标可能给出不同 `node`，`max by (id, name, node)` 会出现两行。去重校验面板（P6）用 `count(count by (id) (pve_guest_info{id=~"qemu/.*"}))` 和 `count(pve_guest_info{id=~"qemu/.*"})` 对比发现此问题。

### 5.2 VM 综合状态（总览落点图、清单「状态」列）

```promql
max by (vmid) (
    # 60 / 40：该 VM 有 critical / warning 告警
    (count by (vmid) (ALERTS{alertstate="firing",severity="critical"}) * 0 + 60)
  or
    (count by (vmid) (ALERTS{alertstate="firing",severity="warning"}) * 0 + 40)
  or
    # 50：深度采集已接入但 up==0
    ((max by (vmid) (up{job="‹node_job›"}) == 0) * 0 + 50)
  or
    # 20：PVE 显示停止
    ((label_replace(max by (id) (pve_up{id=~"qemu/.*"}), "vmid","$1","id","qemu/(\\d+)") == 0) * 0 + 20)
  or
    # 10：其余运行中的 VM
    ((label_replace(max by (id) (pve_up{id=~"qemu/.*"}), "vmid","$1","id","qemu/(\\d+)") == 1) * 0 + 10)
)
```

写法要点：先用比较运算**过滤**出满足条件的序列，再 `* 0 + 码` 赋值。不能写成 `码 * (x == 0)`，那样结果是 0。

（`or` 只保留左侧没有的 vmid，因此要么按严重度从高到低排，要么外层 `max by (vmid)`；上式两者都做了。告警规则若没有 `vmid` 标签，先用 `instance` 或 `hostname` 做 `label_replace` 映射。）

### 5.3 深度采集三态

```promql
# 10 在线 / 50 采集失败 / 13 未接入
  ((max by (vmid) (up{job="‹node_job›"}) == 1) * 0 + 10)
or ((max by (vmid) (up{job="‹node_job›"}) == 0) * 0 + 50)
or (label_replace(max by (id) (pve_guest_info{id=~"qemu/.*"}), "vmid","$1","id","qemu/(\\d+)") * 0 + 13)
```

「未接入」= PVE 有这台 VM、Prometheus 没有该 vmid 的抓取目标。只要抓取目标还在配置里，`up` 就一直存在（值为 0），所以「离线」不会被误判为「未接入」。

### 5.4 「不支持」不填 0

```promql
# 网络列：只对支持的主机返回速率
rate(‹dk_net_rx›[5m]) and on (hostname) (‹dk_net_cap› == 1)
```

不支持的主机查询无结果 → 列的 `noValue` 设为空，再增加一个查询 `‹dk_net_cap› == 0` 生成「能力」字段，通过表格 value mapping 显示「不支持」。不要用 `or vector(0)`。

### 5.5 Docker 新鲜度与采集状态

```promql
# 采集年龄（秒）
time() - max by (hostname) (node_textfile_mtime_seconds{file=~"‹docker 文件名模式›"})

# 主机采集状态：50 失败 / 30 陈旧 / 10 正常
  ((max by (hostname) (‹dk_ok›) == 0) * 0 + 50)
or (((time() - max by (hostname) (node_textfile_mtime_seconds{file=~"‹…›"})) > ‹3×周期›) * 0 + 30)
or (max by (hostname) (‹dk_ok›) * 0 + 10)
```

### 5.6 变量

| 看板 | 变量 | 定义 | 备注 |
|---|---|---|---|
| ② | `node` | `label_values(pve_guest_info{id=~"qemu/.*"}, node)` | 单选 + All |
| ③④ | `group` | `label_values(up{job="‹node_job›"}, group)` | 多选，默认 All |
| ④ | `dhost` | `label_values(‹dk_ok›, hostname)` | **只取 Docker 主机** |
| ⑤ | `vmid` | `query_result(max by (disp) (label_join(label_replace(pve_guest_info{id=~"qemu/.*"},"vmid","$1","id","qemu/(\\d+)"),"disp"," · ","vmid","name")))`，正则 `/disp="(?<text>(?<value>\d+) · [^"]*)"/` | 单选，无 All；21 台全列，含未接入 |
| ⑥ | `dhost` / `container` | `label_values(‹dk_up›, hostname)` / `label_values(‹dk_up›{hostname="$dhost"}, container)` | 单选 |
| H9 | `node`（隐藏） | 同 ② | 供 repeat |

### 5.7 总览 H9「节点落点图」做法

Stat 面板，`repeat: node`，`maxPerRow: 6`；查询为 §5.2 再 `* on (vmid) group_left(node) …` 过滤 `node="$node"`；Legend 用 `{{disp}}`；Text mode = *Value and name*，Color mode = *Background*；value mapping 把状态码映射成「运行中/已停止/警告/故障/采集失败」，颜色按 §3.1。VM 名称后缀「·未接入」通过对未接入集合做一次 `label_replace` 生成 `disp` 实现。

## 8. 实施说明（原生 Grafana 13，不需要插件）

1. **备份**：`GET /api/dashboards/uid/sge-systems`、`…/sge-containers` 导出 JSON，连同版本号存档；记录当前组织首页设置。
2. **并存**：v2 使用新 UID（`sge-v2-home/pve/vms/docker/vm/container`）、新文件夹「SGE 运维监控 v2」，tag `sge-v2-nav` / `sge-v2-detail`。旧看板 UID、内容、文件夹均不动。
3. **生成**：在现有 `prometheus_onboarding_platform.py` 中新增 v2 生成函数，复用现有 PromQL 与清单字典；用同一份字典生成用途/IP 映射、group 归属。
4. **核实先行**（上线前执行，结果写入新记录，不改旧验收报告）：
   - `count by (__name__) ({__name__=~"pve_.*", id=~"node/.*"})`：确定节点级指标是否存在。
   - `count by (__name__) ({__name__=~"pve_.*", id=~"storage/.*"})`：确定存储指标。
   - `count(count by (id) (pve_guest_info{id=~"qemu/.*"}))` 应为 21。
   - `count(up{job="‹node_job›"})` 应为 17；`count(count by (hostname) (‹dk_ok›))` 应为 10。
   - 告警规则是否带 `vmid`/`hostname`/`container` 标签（决定 §5.2 与告警表钻取的写法）。
   - 本实例 Grafana 是否启用动态看板（仅影响 §4⑤ 的可选优化）。
5. **验收协调**：现有验收检查继续指向旧 UID 并应全部通过；为 v2 新增独立检查项（面板数、变量来源、21/17/10/50 计数、「不支持/未接入/未配置」不出现绿色或 0）。
6. **切换**：用户确认后，才把组织首页设为 `sge-v2-home`；旧看板保留至少一个数据保留周期（15 天）后再讨论是否归档。
7. **回退**：把首页设回原值即可；v2 文件夹可整体删除，不影响旧看板。
