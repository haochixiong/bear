### 1.5 程序能否启动、能否打开 JPG

在 offscreen 模式下实测：

- `ColorPickerApp` 能正常创建和显示，带 sRGB ICC 的 JPG 和无 ICC 的 JPG 都能打开并显示。
- 双击取色可以用：取的是 1×1 像素，取到的颜色加入色板。
- 拖框会把框内**所有不同的 RGB 值**加入色板。在一个两色 JPG 的边界上框 30×30，得到 8 种“颜色”，来源是 JPEG 压缩误差，没有统计意义。
- **EXIF 方向被忽略**：Orientation=6 的 JPG 在 Photoshop 中是竖图，在本程序中仍按 400×300 横图显示。坐标会和摄影师看到的画面对不上。
- **ICC 被忽略**：`Image.open(path).convert("RGB")` 直接丢掉了配置文件，Adobe RGB 的图会被当作 sRGB 计算。
- **损坏的 JPG**：Pillow 抛出 `OSError: Truncated File Read`，`upload_image()` 没有捕获，项目也没有安装 `sys.excepthook`。PyQt6 遇到槽函数中未捕获的异常会直接终止程序。
- **大图性能**：`np.unique` 在主线程执行。对 24MP 随机噪声图（最坏情况）实测 **43 秒**，期间界面完全卡住。

## 2. 当前取色链路

```
QFileDialog（png/jpg/jpeg）
  → PIL.Image.open(path).convert("RGB")        ← 丢弃 ICC，不处理 EXIF 方向，没有异常处理
  → self.image（PIL Image，整图常驻内存）
  → display_image(): np.array → QImage(RGB888) → QPixmap → QGraphicsPixmapItem

ImageViewer（QGraphicsView，ui/image_viewer.py）
  ├─ 滚轮：主窗口 eventFilter 处理缩放（0.1×～10×），可以“锁定缩放”
  ├─ 左键拖动：总是框选（没有平移功能，DragMode=NoDrag；README 说的“拖动平移”并不存在）
  │     释放后：选区框被删除 → extract_colors_from_selection(rect)
  │        → crop → np.unique（所有不同的 RGB）→ 加入色板（最多 333 色）
  └─ 双击：pick_color_from_pixel → image.getpixel（1×1）→ 加入色板 + 历史记录

“主色”按钮：整图 resize 到 150×150（不保持比例）→ 在 RGB 空间做 KMeans(k, n_init=10)，在主线程执行
“屏幕取色”：全屏截图加放大镜（对诊断没有用）
```

色彩数学（`core/color_math.py`，基于 Python 标量，没有向量化）：

| 函数 | 审计结论 |
|---|---|
| `rgb_to_lab` | sRGB/D65，结果正确：(255,0,0) → (53.2408, 80.0925, 67.2032)，和参考值一致到 4 位小数 |
| `rgb_to_hsv`/`hsv_to_rgb` | **反变换用 `int()` 截断**，往返误差为 1 的情况约占 47% |
| `rgb_to_hsl`/`hsl_to_rgb` | **返回顺序其实是 (h, l, s)**（colorsys 的 HLS），函数名有误导；同样有截断问题，往返误差约占 71% |
| OKLab / OKLCH / ΔE00 / LCh | **不存在** |
| `color_distance` | 在 RGB 空间算欧氏距离，不是感知色差 |

结论：上游的数学函数只能作为对照基准，不能直接用于诊断。

另外检查了网络调用：上游运行时代码中没有 `urllib`、`requests`、`socket` 或 `QNetwork`，可以完全离线运行。

## 5. 实现方案对比

### 方案A：在上游基础上原地扩展（推荐）

把上游代码整体导入本仓库，并记录 SHA。主窗口中央改成 `QSplitter[ImageViewer | AnalysisPanel]`。新逻辑全部放进新模块，`RNV_Color_Picker.py` 只增加大约 100 行接线代码。

- 优点：符合“保留现有查看器和整体结构”的要求；色板、导出、主题、历史、打包脚本都能继续用；约 1950 个上游测试仍然有效；改动集中，容易审查。
- 缺点：会继承上游的“品牌治理”测试。这些测试会**扫描整个仓库的所有 `.py` 文件**，要求颜色字面量只能写在 `utils/config.py`、README 中的测试数量只能多不能少，等等。我们新增的代码也必须遵守。上游主窗口有一部分控件是用绝对坐标定位的（复选框、调试标签），改布局时需要留意。

### 方案B：新建主窗口，复用上游组件

新建 `portrait_diagnoser.py` 主窗口，复用 `ImageViewer`、主题、日志、线程等组件。原来的 `RNV_Color_Picker.py` 保持不变，作为另一个独立程序。

- 优点：新界面干净，完全不碰 2249 行的主窗口文件。
- 缺点：有两个入口。色板和导出功能要重新接入，否则就和诊断功能脱节，不完全符合“保留并完善 RNV 现有功能”。界面代码更多。

### 方案C：全新的精简应用

只借鉴上游的思路，不继承上游代码结构。

- 优点：最干净，依赖最少。
- 缺点：违背“不要重写整个应用”的要求，还会失去上游的测试基线。不推荐。

## 6. 推荐的第一版设计（方案A）

### 6.1 数据流

```
JPG 路径
 → color_management.load_jpeg(path) → AnalysisImage
      · 只读打开文件；使用 exif_transpose；ICC 转换到 sRGB（相对比色意图）
      · 元数据：原始 ICC 描述、分析空间="sRGB IEC61966-2.1"、是否发生转换、是否假定为 sRGB、
                EXIF 方向、警告列表（例如“未发现ICC，已假定为sRGB”“源色域比 sRGB 宽，可能有裁切”）
 → 显示：直接显示 AnalysisImage 的缓冲区，保证显示坐标和分析坐标完全一致
 → 用户操作 → SampleRequest（点及半径，或矩形；在像素坐标中裁剪到图像范围）
 → 在 QThread 中运行：region_statistics → portrait_analysis / diagnosis_rules → recommendations
 → 生成 frozen dataclass 报告 → AnalysisPanel 渲染
```

核心模块只依赖 NumPy、Pillow 和 scikit-learn，**不 import PyQt**。界面层不写任何色彩公式。

### 6.2 模式与交互

顶部有一排模式按钮：**单点取色 | 通用区域 | 人像肤色 | 参考对比**。

- 单点：单击取色。采样半径可选 1×1、3×3、**5×5（默认）**，或自定义半径。画面上显示取样框。
- 区域和肤色模式：左键拖动框选，松开后选区保留在画面上，可以清除或重新选择。
- 参考对比：先框“参考区”，再框“问题区”，两个区域分别用带标签的矩形标出，任一区域都可以重新选。
- 平移：中键拖动，或按住空格拖动。滚轮缩放。“适应窗口”沿用上游的 Reset Zoom（Ctrl+0）。
- 历史记录：保存本次会话的取样和选区，点击可以回看结果。上游的颜色历史功能保持不变。

### 6.3 统计（region_statistics）

- **采样**：选区像素数不超过 262,144 时全部参与计算。超过时用确定性的分层网格采样（固定步长，不使用随机数），并显示“采样 N / 共 M 像素”。主色聚类再从中取 ≤20,000 个像素，使用固定随机种子。
- **统计量**：RGB 均值和中位数；Lab 均值和中位数；OKLab 和 OKLCH 均值；L* 和 C* 的标准差；L* 的 P10、P50、P90；高光比例和阴影比例；剪切像素比例（有通道为 0 或 255）；C* 直方图。
- **色相**：只统计 C* ≥ C_min 的像素，以 C* 为权重做圆形平均。离散度用 `1 − R`（R 是平均合成向量的长度）和圆形标准差表示。可用像素太少时，标记为“色相不可靠”，并降低置信度。
- **主色**：在 Lab 空间做 KMeans，k 从 2 到 6 自动选择；ΔE00 小于约 3 的簇会合并。每个簇给出颜色、占比、L*、C*、h°。
- **异常色**：先确定主色调和主簇。异常像素的条件是：与主色调的色相差 ≥ 90°，且 C* 高于“噪声地板”，或者与主簇的 ΔE00 很大。同时计算**空间聚集度**，即异常像素的 4 邻域中也是异常像素的比例。这样可以区分零散的噪点和成片的污染（例如反光）。

### 6.4 诊断规则：避免误报是核心

7 个风险分项都输出数值、严重程度（正常、轻微、明显、较强）、证据和置信度。总分是带上限的加权组合，**界面始终同时显示各分项**。

| 分项 | 判定思路 | 防误报设计 |
|---|---|---|
| 对立色混入 | 主色调占多数，同时存在 ≥1% 的少数簇，与主色调相差 120°～180°，并且 C* 高于噪声地板 | 两种对立色各占 ≥25～30% 时，判为“双主色/可能是有意配色”（例如青橙风格），不算污染。零散分布的点归为噪点，最高只判“轻微” |
| 色相离散 | 以色度加权的圆形离散度 | 选区色度很低时色相没有意义，这一项不计分，并说明原因 |
| 色度压缩 | 有参考区时，比较 ΔC*；肤色模式下，看 C* 是否低于“按 L* 变化的期望色度区间”；通用模式下，只有色度低**并且**伴随离散或混色时才计分 | **单纯低饱和不判为脏**：灰蓝色如果色相集中，应判为“低饱和、干净” |
| 局部偏色 | 按 L* 分成阴影、中间调、高光三段，比较各段的 a*、b* 和 h° | 只有分段之间的差异超过阈值才报告，整体统一的暖色调不算 |
| 明度压缩 | P90 − P10 的宽度 | **暗调本身不是问题**：只作为辅助证据，单独出现时最多判“轻微” |
| 异常色比例 | 异常像素占比乘以空间聚集度 | 少量噪点不会得出严重结论 |
| 置信度 | 由采样数、平均色度（决定色相是否可靠）、剪切比例、是否假定为 sRGB、选区是否混杂（L* 或色相呈双峰，可能框进了头发、眼睛或背景）综合得出 | 置信度低时，结论自动降级为“倾向” |

每条结论都按固定结构输出：**问题、证据（附数值）、可能原因、调整方向、置信度、注意事项**。

### 6.5 人像肤色（portrait_analysis）

- **总体倾向**：主要依据 Lab 色相角 h°。各种深浅的肤色 h° 大多集中在一个红到黄的区间。结合 a*/b* 的比例和 OKLCH 色相，判断偏红、偏黄、偏洋红、偏绿或偏青。色相受明度影响较小，所以**同一套色相区间可以用于深色和浅色肤色**。色度的期望区间则随 L* 变化。
- **高光发黄**：比较 L* 最高 15% 像素和中间调的 Δh 与 Δb*。
- **阴影发青或发绿**：比较 L* 最低 15% 像素的 a* 下降量，以及色相向绿、青方向的偏移。
- **脏、灰、不透亮**：色度低于期望区间，并且伴随色相离散或对立色成分。
- **注意事项**：自动提示可能受到妆容、环境光、彩色反射或选区混入非皮肤区域的影响。
- **阈值的定位**：第一版的经验区间先写成集中的、带注释的参数表，并在界面上标明“经验值”。**需要你用真实样片校准**，这是主要风险。

### 6.6 参考对比

输出 ΔE00、ΔL*、ΔC*、ΔH* 和 Δh、Δa*、Δb*。同时把差异分解到“参考区色相方向”和“垂直方向”，用来表示对立色成分的变化。还会并排比较两个区域的 P10/P50/P90、C* 分布和色相离散度。

只要设置了参考区，就**优先使用相对比较**的结论。

### 6.7 调整建议（recommendations）

用一张映射表，把诊断结果映射为调整方向。例如：

- 问题区比参考区 b* 高（偏黄）：可以把色温向蓝移动，或在 HSL 中把黄、橙的色相向红调、饱和度降低，必要时局部处理。
- a* 偏低（偏绿）：Tint 向洋红移动。
- 阴影发青：在颜色分级中给阴影加红或橙；或在曲线中，把红通道的暗部抬高。
- 色度压缩：在 HSL 中提高橙色饱和度，或提高自然饱和度；同时检查去朦胧和清晰度是否过度。
- 反射色污染：用局部蒙版降低对应色相的饱和度。
- 也可以给出 Photoshop 可选颜色的大致方向。

强度分为“轻微、小幅、中等”，根据 |Δ| 分档，并**明确标注是估计值**。**不给出 ACR 滑块数值。**

### 6.8 界面

- 左侧是看图区，右侧是 `AnalysisPanel`，分为取色信息、区域统计、人像诊断、参考对比、调整建议几部分。
- 默认只显示结论卡片和关键证据，详细统计放在可展开区域里。
- 界面文字用中文，专业参数保留英文缩写，例如“明度 L*”“色差 ΔE00”。
- 上游的色板区缩小到底部，可以折叠，功能保持不变。

## 8. 风险

- 肤色经验阈值没有经过真实样片校准，第一版只能称为“倾向”。
- 转换到 sRGB 分析空间时，宽色域源图（例如 Adobe RGB）的高饱和颜色会被裁切。我们会统计并提示裁切比例。
- 显示没有按显示器 ICC 做色彩管理（Qt 的限制），但分析使用的是转换后的原始像素，不受影响。
- 上游治理测试会扫描新代码，开发时要遵守它的约定。
- 本环境无法生成和验证 Windows exe，需要你在 Windows 上做人工验证。
