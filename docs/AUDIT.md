## 已修复

### 会误导修图的问题（最重要）

| 问题 | 修复 |
|---|---|
| 颜色分级建议用的是目标色调的**绝对值**，不是“目标 − 当前”。例如阴影已经偏黄，还建议继续加黄 | 风格模板和仿色都改为按差值换算；有回归测试 |
| ACR 预设导出拿不到混色器和颜色分级数值（整图和仿色模式的建议在结论里，没被收集），导出几乎是空的 | 从结论、风格结果、仿色曲线一起收集并去重 |
| 非肤色的“参考对比”给出的是肤色建议（只在红色 / 黄色范围里找，还写着“只作用于皮肤”） | 按区域本身的色相从六个 PS 范围里选；措辞和 ACR 通道也随之改变 |
| 肤色提亮可能被做两次：通道曲线已含明度，又单独给了一条复合曲线 | 有明度差时，通道曲线只改颜色，明度另用复合曲线 |
| 自动生成的图层直接把 Lab 色相度数当成 PS（HSB）滑块值（绿色约差 2 倍，肤色约差一半）；肤色用“黄色”范围，皮肤只落在它的边缘 | 先换算到 HSB；色相/饱和度范围以问题色为中心 |
| 半透明图层的透明部分被当成灰色参与统计（例如 6:3:1 里多出 22% 的“灰”） | 脏色和肤色分析用不透明蒙版；整体统计用本图层的不透明像素重采样填充 |
| “色相杂乱”的建议是“降低‘肤色’的饱和度”（ACR 没有这个通道） | 改为把两侧相邻通道的色相往主色收拢 |
| 肤色倾向在 0° 附近跳变；偏青的皮肤被说成“偏洋红”；“偏绿”可能给出负的度数 | 色相改为连续计算；增加“偏青/偏蓝”；度数不为负 |
| 浅肤色（日系、韩系、cos 的 C*/L* 约 0.14–0.22）在“自然通用”下被判为发灰 | 没选具体风格时，按明度参考所有内置风格的饱和度范围 |
| RAW 用 LibRaw 默认的 BT.709 曲线解码，中灰约暗 13 级 | 改用 sRGB 曲线 |
| 自定义肤色风格的色相区间跨过 0° 时判断错误；仿色曲线可能有重复输入点；取样大小标签没反映上限裁切 | 均已修正 |

### 桌面版

- 在其他模式下切换“风格”，会把已有的肤色结果替换掉。
- 仿色的参考作品一旦选过就换不掉，清空历史后仍沿用。现在有“更换参考作品”按钮。
- 打包后的窗口程序里，错误处理本身会报错，错误对话框弹不出来。
- `--help` / `--version` 会启动界面，而不是打印帮助。
- AI 命令行方式：
  - Windows 下带引号的路径找不到；
  - 超时后 node 子进程不退出；
  - 缩略图不删除；
  - AI 回复按 HTML 渲染。
- 框选层被系统关闭（如 Alt+F4）后，主窗口一直隐藏。
- 快捷键：一个无效时，另一个已被保存。
- 分析尚未结束就关窗口时，后台结果回调报错。

### 本机服务（插件后端）

- **DNS 重绑定**：现在只接受以 127.0.0.1 / localhost 访问。
- **输入校验**：
  - 负数或超大的 Content-Length、尺寸返回 400，不会挂起，也不会耗尽内存；
  - 非法 JSON 返回 400；
  - 内部错误返回 500 并附中文原因（以前直接断开连接，插件只能显示“连不上”）。
- **校准**：
  - 拒绝尺寸不对的色卡；
  - 拒绝空的拟合，不会覆盖已有校准；
  - 加锁，限制样本数量。
- **蒙版**：
  - 可以返回整幅文档大小、分析范围以外为 0 的蒙版，局部图层生成的调整不会作用到范围以外；
  - 放大改用 Pillow，6000×4000 约 0.13 秒（以前约 7 秒，PS 会卡住）。

### PS 插件

- batchPlay 出错不会抛异常。现在逐步检查返回结果和新图层 ID，避免把原图层改名或把蒙版写到原图层上。
- 先取回全部蒙版再建图层；中途失败时不提交历史记录（整体撤回）。
- 图层类型按 PS 自己的 `constants.LayerKind` 取值，避免名字写错漏判。
- ACR 校准在单独的色卡文档里进行，结束后关闭；“合并可见图层”生成 Camera Raw 图层时改用盖印可见图层。
- 打开 Camera Raw 对话框时使用 interactive 模式。

### 打包与文档

- 两种构建方式都安装 Claude API、RAW、AI 抠皮肤的依赖。
- 模型下载遇到 HTTP 错误就失败，并做 SHA-256 校验。
- README 的“已知限制”、测试数量、插件启动方式等与代码不一致的地方已更正。
- README 写明 API Key 以明文保存在本机设置里。

## 只能在 Windows 上确认（已写进交接文档）

1. **显示器 ICC**：较新的 Qt 6 在 Windows 上 `QScreen.name()` 可能返回型号名。现在先按屏幕位置找 GDI 设备名，需要在真机上确认能读到 ICC。
2. **全局快捷键**：
   - `nativeEventFilter` 的返回值目前是 `(bool, 0)`，需要确认 PyQt6 接受；
   - `RegisterHotKey` 在菜单 / 原生对话框打开期间收不到。
3. **插件**：
   - `putLayerMask` 写入整幅文档蒙版的效果；
   - 各调整图层描述符；
   - Camera Raw 描述符（见 `STAGE6_HANDOFF.md` P1–P10）。

## B. 核心算法（未修复）

| # | 程度 | 位置 | 问题 |
|---|---|---|---|
| B1 | 会误导 | `layer_plan.py` 仿色曲线 | 去重时 `(255,255)` 覆盖了参考点 `(255,x)`：PS 曲线图层和 ACR 导出不一致 |
| B2 | 会误导 | `reference_match.py` `_neutral_cast` | 中性像素太少时返回 (0,0)，被当成“中性”；例如自己阴影已经很蓝，仍建议往阴影加蓝 |
| B3 | 会误导 | `palette.py` `_style_adjustments` | 阴影/高光色调已达标时仍给颜色分级建议；色相范围为 [0,360] 的规格（如黑金阴影）会给出随机色相 |
| B4 | 会误导 | `analysis.py` 肤色整体偏色 | 以“自然肤色”的明度为目标，会让深肤色提亮、浅肤色压暗（应 `keep_lightness=True`） |
| B5 | 会误导 | `acr_preset.py` | 同一通道来自不同建议的数值被相加；低于门槛的值和 0 也被写入，会重置用户已有滑块；“相对量”被写成绝对值 |
| B6 | 性能 | `layer_plan.py` 羽化 | 2400 万像素生成图层方案约 20 秒（盒式模糊占约 19 秒）；应在分析分辨率上羽化再放大 |
| B7 | 边界 | `portrait_analysis.py` `preset_fit` | 色相区间写成 lo > hi（如 [350, 20]）时永远判为不在范围内 |
| B8 | 边界 | `_expected_saturation` | 明度 > 93 时下限突然从 0.08 跳到 0.24，极亮皮肤会被误报发灰 |
| B9 | 边界 | `tendency_of` | 选区接近纯灰时报“偏青/偏蓝 150°”；应在 C* < 4 时视为正常 |
| B10 | 细节 | `acr_preset.py` | 空曲线报错；色相 370 被截成 359 而不是 10；`ProcessVersion` 写死 11.0、`ConvertToGrayscale=False`、未写 `ToneCurveName2012`，三处需在真实 ACR 确认 |
| B11 | 细节 | 校准 | `sat_per_unit` 按 Lab 色度比例拟合，使用时却按 HSB 饱和度换算，高饱和时有偏差 |
